# SOP 模块数据设计

状态：图文SOP、固定版本关联后台及前端已实现，见 [接口文档](../../../SOP_Server_of_Java/docs/sop/README.md)；统一制作需执行文末制作增量迁移，不重建七表。本次未在实际MySQL执行。SQL见 [建表入口](../../sop-module-v1/README.md) 和 [schema.sql](../../sop-module-v1/schema.sql)。本设计以现有用户、项目、成员状态及归档恢复为基础，不限定装配行业。

## 第一版流程

创建SOP → 编写步骤/附件 → 保存草稿 → 发布版本 → 关联项目或子项目 → 只读预览。

不包含生产任务分发、执行打卡、工位/设备防错、审核签章、执行阶段语音联动。区域标注已接入统一制作界面，旧演示保留隐藏入口，也不把等待检测、Andon等字段强制加入通用步骤。

## 所属项目与复用

每份SOP有且只有一个管理项目（managing_project_id），负责成员协作和权限范围；SOP与其版本独立于具体子项目存储。管理项目在创建后不移动，编号全平台唯一且不可修改。这样先复用现有项目权限，不引入公开资料库或另一套SOP成员系统。

一份SOP可关联多个项目/子项目，关联固定到某个已发布版本。管理归属并不自动产生使用关联，创建后由用户明确选择挂到主项目或子项目。主项目的关联也不自动继承到全部子项目，避免重复和隐式执行顺序。

```text
管理项目 ── SOP（稳定编号、负责人）
              ├─ V1 已发布 ── 步骤 ── 附件引用 ── 文件
              └─ V2 草稿   ── 步骤 ── 附件引用 ── 文件

使用项目 A ── 关联某 SOP 的 V1
子项目 B   ── 关联同 SOP 的 V1 或另一已发布版本
```

跨项目复用不等于公开：新增关联的人必须有目标项目的编辑/管理能力，同时有源SOP的访问权。另一项目的成员只可通过有效关联查看那个版本及附件，不因此获得源项目、其他版本、草稿或编辑权限。

## 基础七表与制作配置扩展

| 表 | 职责 | 关键约束 |
|---|---|---|
| sop_document | SOP身份及管理归属 | code全局唯一，name、管理项目、负责人；负责人引用管理项目成员 |
| sop_revision | 每版完整内容和发布状态 | SOP内revision_no唯一；同一SOP最多一个有效草稿；保存标题、范围、目的、总注意事项及修订说明 |
| sop_step | 某版本的操作步骤 | 顺序、标题、操作说明、注意事项、检查要求、可选参考时长 |
| sop_file | 不可变文件对象的元数据 | 随机storage_key唯一、原名、类型、字节数、SHA256、上传人；文件本体在私有存储中 |
| sop_step_attachment | 步骤引用的文件 | 同一步骤不重复引用同一文件，可设置顺序和说明 |
| sop_project_binding | 主项目选择的SOP版本 | 一个项目同一SOP只保留一条当前关联；解绑保留行 |
| sop_subproject_binding | 子项目选择的SOP版本 | 一个子项目同一SOP只保留一条当前关联；父项目由子项目真实归属推导 |

分开两张关联表，是为让主项目和子项目都有真实外键，避免使用type+target_id却无法保证对象存在。关联的(sop_id,revision_id)复合外键保证版本属于该SOP；是否已发布、有效及有权限仍由后端校验。

原schema保持不变，本脚本仅新增七表。已有用户、项目建表及项目001/002迁移必须先完成。DDL只保证基本字段、唯一性和引用，不保证发布内容不可修改，也不能代替授权。

## 字段与内容规则

- 所有ID使用有符号BIGINT，接口按字符串返回；UTC毫秒时间，输出ISO8601。可编辑聚合根使用version，冲突409。
- 新code由前端自动生成SOP-12位时间戳-6位随机码，旧编号保持不变；删除后不复用。name和版本title为1–128字符。文档name用于当前目录，历史预览必须用版本title，防止改名改变旧版本显示。
- applicable_scope可空，最多1000字符；purpose和precautions可空，应用分别限制5000字符；revision_note最多1000字符。首次发布可空修订说明，后续版本发布必须说明变化。
- 步骤title必填1–128字符，instruction必填、应用最多10000字符；precautions/check_requirements可空、各最多5000字符。使用纯文本，前端按文本展示，不接受任意HTML。
- expected_duration_seconds可空，非负秒数，两位小数；它是参考作业时长，不是设备检测等待时间。工位、工具、设备不是必填项，后续按需关联。
- 步骤和附件顺序从1开始，最终保存时由服务层整理为连续序号。数据库允许临时重复顺序以便事务内重排，读取按sort_order、id稳定排序，发布前拒绝重复/不连续顺序。
- SOP负责人创建时必须为管理项目的正常、未删除、有效编辑成员；外键只保证成员行存在，有效状态和编辑等级由服务层检查。

## 版本生命周期

版本状态：0草稿、1已发布、2已停用。revision_no从1递增，界面显示V1、V2等，不使用小数版本。草稿创建时分配编号，放弃草稿后不复用编号，允许出现跳号。

1. 创建SOP时同事务创建V1草稿，可以没有步骤，但不能发布空SOP。
2. 同一SOP最多一个未删除草稿；生成草稿槽位唯一索引作为并发兜底。修改草稿不是创建新版本，每次保存增加version。
3. 修改已发布内容时，选择该SOP的一个已发布/已停用历史版本复制为新草稿。复制版本头、步骤和附件说明，生成新的步骤/附件关联ID；不可变文件对象可继续引用。原版本完全保留。
4. 发布前检查版本/步骤必填、至少一个步骤、顺序、文件存在且可读、负责人有效、管理项目可编辑及修订说明。发布是事务：锁定聚合、重新验证、设置发布人时间并递增版本。
5. 发布后标题、范围、说明、步骤、附件及文件内容不可修改；只能创建新草稿或停用版本。数据库账号不直接对外开放写入，所有写接口须检查版本状态。
6. 新版发布不会自动停用旧版，也不切换已有项目关联。最新可用版通过最大已发布revision_no查询，不建立循环外键指针。列表显示“有新版本可切换”，用户明确选择后才更新关联。
7. 停用仅允许已发布版本，必须先替换/解绑仍在未开始或进行中的项目/子项目的有效使用关联；已完成/归档目标的冻结关联只作历史查阅，不阻止停用。停用后不允许新关联，不允许原地恢复发布。需再使用时复制为新草稿重新发布。历史预览仍可按权限查阅。
8. 只允许删除从未发布、没有任何关联记录的SOP；文档软删除，同事务将有效草稿标为已删除。仅草稿可单独放弃；已发布/已停用版本永久保留，不物理删除步骤和引用。

草稿的步骤/附件可以在服务层授权、锁定草稿后物理删除；这不影响其他版本。旧草稿已删除后保留的附件仍视作文件引用，第一版不清理这些文件，以免误删历史内容。

## 项目关联与历史

绑定前校验目标项目/子项目存在、未删除且未完成/归档；源管理项目未删除，SOP未删除，版本已发布，操作者具备源访问及目标编辑能力。新绑定与切换版本都走显式操作，提交target_version（主项目或子项目当前version）；切换/恢复/解绑另提交关联version，排序提交target_version。

同一目标每份SOP只有一个当前版本；更新选择时递增关联version。status=0表示解绑，保留最后一次选择的版本和关联行，重新关联复用该行。关联表保存当前选择及最后解绑状态，不是完整关联变更历史。未来执行任务必须另存revision_id，不能通过可变的当前关联推断当时标准。

目标项目/子项目完成或归档后关联只读；恢复项目不自动升级SOP。如果固定版本已停用，恢复后显示“版本已停用，需切换”，保留历史预览；不能把它作为新任务标准，需先选择已发布版本。子项目的关联只有在父项目及子项目都未完成/归档时才视为当前使用。管理项目归档后不能修改/发布其SOP，但已发布版本可供有权限的人继续查阅或选择复用。主项目/子项目曾有SOP关联时，即使后来解绑，也不允许删除，只能归档保留上下文。

## 授权设计

规划功能码：sop:list/read/create/update/publish/retire/delete/bind。功能码由可选permissions.sql定义，本批补充sop:bind到编写/负责人角色，可重复执行更新。负责人交接按root/管理项目负责人身份校验，不靠一个全局功能码越过项目范围。不自动写入开发库或为用户分配角色。

| 操作 | 数据范围与角色约束 |
|---|---|
| 查看SOP草稿和全部版本 | 管理项目有效成员，具备project:read和sop:read；root/主项目负责人按项目管理能力处理 |
| 新建/编辑草稿 | 管理项目有效编辑成员及对应sop:create/update功能；管理项目必须可编辑 |
| 发布/停用 | root、管理项目负责人，或有对应功能权限的SOP负责人；普通编辑成员不能仅靠编辑权限发布 |
| 转移SOP负责人 | root或管理项目负责人；新负责人必须为正常有效编辑成员；完成/归档项目允许人员交接，内容不变 |
| 绑定/切换/解绑 | 目标项目负责人或有效编辑成员，普通成员还需sop:bind及目标查看权限；新增/切换另需源SOP访问权 |
| 从使用项目预览 | 目标项目有效查看成员及项目查看权限，仅限有效关联的固定版本及附件；已停用版本标记为历史，不允许新任务使用 |

root仍须遵守业务版本不可改、项目归档只读等规则。项目成员移除、降级或账号禁用后，每次请求重新校验；复用方成员不获得源SOP草稿访问权。新建SOP不自动授予系统角色，前端展示缺少权限及管理项目范围。

## 附件上传与访问

第一版实现优先图片；表结构预留视频及PDF，接口未实现的类型不展示入口。当前支持PNG/JPEG≤5MiB，每步骤最多20张，最大边长8192、总像素1600万；服务端实际解码校验，不仅信扩展名。WebP、视频和PDF尚无接口。

文件本体不存数据库，不保存浏览器blob URL、base64或任意外部URL。服务端生成随机storage_key，流式校验大小、类型、SHA256，成功落盘/入私有对象存储后才写文件记录。数据库只保存元数据；前端获取file_id和受控预览地址，不能指定或直接获取服务器路径。

文件成功上传后不可覆盖同一对象；更换图片产生新对象。新附件只能引用本人上传且未删除的文件，root可管理；复制历史版本时由服务端在同一SOP内授权复用原引用，不开放按任意file_id“借用”其他人的文件。

文件下载按源版本访问权或目标项目有效关联校验；知道file_id并不等于有权下载。上传即关联具体草稿步骤，不提供未关联文件读取入口。其他用户只能读取其有权查看版本所引用的文件；禁用/删除账号不可用旧链接绕过授权。

当前没有定时清理；进程中断遗留的无引用对象需后续实现引用核对后清理。已有任何草稿/发布/停用版本引用的文件均不自动删除，解绑项目也不删除文件。存储写入与数据库不是分布式事务，失败补偿和清理任务必须处理孤立对象，不向用户误报成功。

## 与现有模块必须一起补齐的规则

**本批已接入项目删除、子项目删除和成员移除/降级检查，及SOP负责人交接；不能仅部署新表而继续运行不含这些检查的旧后台。** 图片存储与绑定检查已随接口实现；未来任务检查在执行模块落地。

- 项目删除：管理了任何未删除SOP，或曾有项目/子项目SOP关联时拒绝；子项目删除检查自身任意关联，包括解绑记录。
- 成员移除/降级：仍为未删除SOP负责人时，先转移SOP负责人；状态校验扩展现有protectOwner逻辑，保留历史外键。新增SOP负责人转移接口，避免只能阻止却无法交接。
- 账号停用/删除不篡改历史发布人和负责人；暂停其访问，由root/管理项目负责人办理交接。操作记录可沿用项目交接记录机制，至少保存SOP编号、目标人及变更前后值，不补造历史。
- 子项目负责人转移不会自动改SOP负责人。二者职责不同，前端明确显示。
- 归档/恢复项目不改版本状态或绑定版本号，恢复后返回已停用关联的提示标志。未来任务上线前再补未结束任务限制、停用版本禁止新任务及执行记录的固定版本引用。

## 并发与事务

写操作先锁涉及用户（ID升序），再锁涉及项目（ID升序），再锁SOP文档（ID升序）、版本、步骤/绑定及文件；所有模块共享这套顺序，不能持有SOP锁再反向获取项目锁。源与目标跨项目时同时按升序锁定；单次读到归属变化需回滚重新获取，不补反向锁。

草稿所有内容写入都锁文档和版本：步骤更新检查步骤及版本version，附件与排序检查版本version；成功递增版本和文档version。发布、复制草稿、放弃草稿、停用锁同一文档，重复发布或过期保存409。文件不可变对象不用编辑version，引用变更受草稿版本锁保护。

关联操作持有同一SOP文档锁，使停用与新关联串行；目标项目/子项目状态及版本在锁后复查。新增与排序递增目标父项目version，子项目关联变更同时递增子项目version。单次绑定修改检查绑定version及目标聚合版本，防止恢复旧页面覆盖别人选择。

只在服务层实现授权/状态/版本检查，数据库约束作为兜底，不能返回数据库异常细节。

## 实现顺序与验收

1. 对齐接口契约及权限码，完成上述既有模块引用检查，再实现SOP基本资料、草稿及步骤。
2. 实现图片私有上传/读取、草稿预览与发布。
3. 实现项目/子项目关联、固定版本预览、显式升级和停用保护。
4. 前端接入SOP列表、详情/版本、编辑器和项目“关联SOP”页签；标注作为可选步骤能力已接入，不提前做现场调度。

验收至少覆盖：同一SOP并发只能有一个草稿、并发发布一次成功、发布后拒绝所有内容写入、复制不会改旧步骤或图片、跨SOP版本绑定被外键拒绝、跨项目不能越权看草稿/文件、目标项目成员移除立即失去关联预览权、发布新版本不改变旧关联、停用被有效关联阻止、SOP负责人移除必须先交接、项目删除被SOP引用阻止、解绑后历史文件保留、版本冲突与上传失败无假成功。

## 验证范围

DDL已做静态核对，文字SOP接口及引用保护通过独立H2库的真实HTTP集成测试，没有在实际MySQL执行，也没有把H2兼容测试当作MySQL验证。应先在独立MySQL 8.4测试库执行本脚本及必要场景，再决定应用到开发库；已有业务表不需要重建。图片私有上传/读取、发布完整性检查、固定版本关联及前端已实现，通过独立H2 HTTP和前端组件测试，真实MySQL与浏览器仍需联调。

## 统一制作升级：步骤设置与图片标注

在已有七表上执行一次[migrations/001_authoring_visual.sql](../../sop-module-v1/migrations/001_authoring_visual.sql)，不重跑schema.sql。增加sop_step的detection_wait_seconds DECIMAL(5,1)默认0、voice_enabled TINYINT默认0、voice_text VARCHAR(1000)可空；增加sop_step_visual，按attachment_id唯一外键关联图片引用，删除草稿引用时级联删除该行。

visual字段：原图宽高、schema_version=1、source_type=upload、guide_items/detection_regions两个JSON数组、创建/修改用户及时间。当前没有摄像头接入，来源仅允许upload，摄像头参考信息在后续RTSP接入时再扩展，不预填模拟设备。每张底图独立标注，复用sop_file不能共享可变标注。

旧附件没有visual行时返回null，旧步骤配置默认等待0/语音关闭，不编造标注。标注写入与步骤、可选版本头同事务；复用草稿版本锁与revision_version乐观校验，不增加独立标注version。复制发布版时复制配置到新的图片引用，保留旧内容。后续执行仍引用SOP发布版本，不直接关联标注表。

脚本含ALTER及CREATE两个DDL，执行失败先核对实际列/表，不盲目重跑；应用不自动执行。本次未在实际开发MySQL执行。完整JSON和权限契约见[后台接口](../../../SOP_Server_of_Java/docs/sop/README.md)。


## 工位与子项目任务

任务属于子项目，直接绑定工位并独立固定发布版本；项目不单独维护工位分配。步骤设备及环境要求随版本保存，旧关联入口保留用于标准查阅。当前行为、权限与启用顺序见 [资源与任务模块](../resource/README.md)。
