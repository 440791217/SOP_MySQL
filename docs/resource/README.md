# 工位、工具设备与子项目 SOP 任务

当前结构：项目 → 子项目 → SOP 任务 → 工位 → 设备；每个任务独立固定 SOP 发布版本。代码与增量脚本已提供，尚未连接实际 MySQL 执行或核对。

## 启用顺序

1. 确认选择 `sop_dev`，已有用户、项目、SOP 七表，并已执行项目迁移 001/002 和 [SOP 制作迁移 001](../../sop-module-v1/migrations/001_authoring_visual.sql)。已完成的脚本不要重复执行。
2. 尚未建资源表时先执行整个 [资源与任务脚本](../../resource-module-v1/schema.sql)，新增七表和 `sop_step.workplace_requirements`；已建则跳过。随后执行一次 [位置与工位 IP 升级脚本](../../resource-module-v1/migrations/001_station_location_ip.sql)，新增位置表、工位位置引用与 IP。不要重跑已执行的脚本。
3. 普通用户需要新权限时，执行 [可重复的权限定义](../../resource-module-v1/permissions.sql)，在用户管理中分配角色后重新登录。root 无需额外角色。
4. 可选执行 [测试位置清单](../../resource-module-v1/test_locations.sql)，也可重启后端和前端后从“位置管理”录入。先建位置，再建工位与设备，最后进入子项目创建 SOP 任务。测试清单可重复执行，不覆盖已有资料、不生成虚假工位 IP。

MySQL DDL 不是整体事务；若执行中断，检查已创建的对象与报错后再处理，不能重复执行整份建表脚本。不要执行已废弃的业务流水号脚本。此批 SQL 未在实际 MySQL 8.4 上执行，独立 H2 测试只验证接口、事务与关联规则，不能代替 MySQL 实际迁移验收。

## 新增表与约束

| 表 | 职责 |
|---|---|
| sop_location | 数据库位置清单：编号、名称、状态、备注、版本及审计字段，支持独立录入和列表 |
| sop_station | 独立工位资料：编号、名称、location_id、ip_address、负责人、状态、备注及审计字段；旧 location 文本保留 |
| sop_resource_model | 工具设备规格：类型代码、型号、规格、单位、状态 |
| sop_resource_device | 实物资料：规格 ID、序列号、当前工位 ID、负责人、状态 |
| sop_device_connection | 每设备一份当前连接配置，修改时由设备 version 并发保护 |
| sop_step_resource_requirement | 步骤要求：规格引用、数量、说明及名称／类型／型号／规格／单位快照 |
| sop_task | 子项目任务：编号、名称、工位、负责人、顺序、配置状态、说明及 version |
| sop_task_standard | 任务固定标准的选择历史；当前 active 记录唯一，通过组合外键核对 SOP 与版本匹配 |

位置、工位、规格、实物、连接和任务包含审计字段。位置被有效工位引用时禁止删除；位置停用后不能用于新建或编辑工位，原关联仍可查看。工位必须选择存在且可用的位置，绑定一个有效 IPv4／IPv6 地址。IP 规范化后通过数据库唯一索引防止有效工位重复绑定；软删除释放地址。历史工位允许暂缺位置或 IP，但保存编辑和任务配置完成前必须补齐。升级自动将原非空位置文本转为清单，保留原文字，不给历史工位填假 IP。

资源与任务使用逻辑删除字段，任务在首批通过取消保留记录，不提供物理删除。编号沿用前端年月日小时分钟加随机码：位置 LOC、工位 STA、规格 TMD、实物 TOL、任务 TSK；数据库唯一约束兜底，不分配服务端流水号。

工位状态和设备状态为 0 可用、1 维护中、2 停用；规格非 0 状态禁止新选用及用于发布新标准。项目不维护另一套工位分配，任务必须属于有效子项目，一个子项目可有多任务，一工位可承接多任务。跨项目、已完成或归档范围禁止写入。

任务状态为 0 待配置、1 已配置、2 已取消。待配置允许缺工位或 SOP；已配置要求工位可用、固定版本已发布且未停用、负责人为正常编辑成员，工位设备数量满足每一步骤的规格要求。按步骤逐项核对，不把不同步骤的数量直接累加。清单返回实时缺项，设备之后维护或移出时会显示待配置提示；已配置不代表设备在线或任务已经运行。暂不提供任务下发、启动、完成、占用预约、执行结果等接口。

资源状态变更不改写历史标准。工位被设备或有效任务引用时不能删除、维护或停用，需先移出设备并调整任务。规格有设备或步骤引用时不能删除。子项目有任何历史任务时不能删除；未取消任务的负责人需先转移任务才能移除或降级其成员身份；有效任务使用的版本禁止停用。

## SOP 要求与固定版本

步骤资源要求及环境要求纳入现有 authoring 保存事务，与步骤、图片标注、可选版本基本资料一起保存；任何校验失败全部回滚。省略 resources 字段兼容原请求，不清空已有要求；传空 items 明确清空。普通步骤文字编辑不会清空资源要求。

初次选择规格时复制快照，后续保存同一规格保留快照；目录更名不静默改变草稿或发布内容。需要使用新目录信息时，在草稿移除该规格、保存，再重新添加。发布后不可修改，复制修订草稿时复制要求快照和环境要求。无资源要求的旧 SOP 正常兼容。

任务可选已有发布 SOP，或从任务入口创建标准并进入现有标注制作界面；草稿发布后，返回子项目配置任务并选择该版本。选择历史单独保存在任务表中，不依赖已有项目／子项目 SOP 绑定，因此切换或解除旧绑定不会改变任务标准。任务版本切换必须显式保存，保留之前选择记录；取消后的任务只读。

## 设备连接范围

类型使用可扩展小写代码：camera、scanner、welding_gun、measuring_tool、other 等。类型与连接方式分开；目前任务按具体规格及数量匹配，不做自动跨规格替代或厂商能力推断。

网络连接记录主机／IP、端口、路径；USB／串口记录接入电脑标识与设备标识；无需连接的普通工具允许无配置。工位单独绑定一个终端 IP；设备另有自己的连接地址并绑定工位，因此一个工位下仍可有多个网络设备 IP 和 USB 设备。两者分别保存，不自动互相覆盖。键盘输入模式的现场标签只用于配置管理，不能凭输入文字可靠识别某台物理扫码枪。

本批不保存设备账号密码，拒绝将完整 URL、凭据或查询参数填入路径。需要认证的摄像头后续在媒体适配层通过受控凭据配置接入；不能把含密码 RTSP URL 写入普通字段。每设备暂支持一份连接配置，不实现多通道并行连接。

首批扫码枪支持前端键盘输入模式：焦点输入、回车结束、短时间重复抑制、工位上下文展示，不持久化扫码执行记录。摄像头支持 RTSP 连接资料和受权限保护的 preview/snapshot 适配状态入口，目前无媒体适配器和实机，明确返回未接入，不产生假视频、假图片或在线状态。从任务进入制作时可查看所属工位的摄像头。视频转码、实时预览与截图入库留待适配器及实机接入后实现和验收。

## 权限与验证

资源目录查询、维护及设备使用分别为 resource:read、resource:manage、resource:use；任务管理为 task:manage，并要求当前项目编辑成员身份和 project:read。root／主项目负责人可管理其子项目任务，但项目负责人不因此获得全局资源维护权限。新选择工位仍需资源查询权限；新引用源 SOP 仍校验源标准读取权限。目标项目查看者可通过任务预览读取固定版本与图片，不额外获得源项目或资源管理权限。

独立 H2 测试覆盖资源与连接配置、乐观锁、项目范围、任务配置缺项、固定版本历史、停用／删除保护、事务回滚、快照及复制兼容；前端组件测试覆盖扫码输入、连接配置、任务创建、制作上下文及资源要求编辑。实机扫码输出模式、摄像头及实际 MySQL 迁移需现场验证。

接口与页面说明见 [后台资源模块](../../../SOP_Server_of_Java/docs/resource/README.md)、[前端资源模块](../../../KedaAdmin/docs/resource/README.md)。


## 设备表单通信配置补齐

2026-10-17 起，设备创建／编辑与 sop_device_connection 配置同事务保存，列表通过 LEFT JOIN 展示通信方式、协议、IP／主机、端口、USB／串口标识；无连接记录的历史设备仍显示。切换通信方式会清空不适用字段。此批复用既有表，无需执行新增 SQL。

设备 code 由前端自动生成，数据库唯一约束兜底；serial_number 是可选的厂家出厂序列号，不替代自动设备编号。工位 IP 与设备网络地址分别保存。


## 2026-10-17 工位任务入口

工位详情增加 SOP 任务清单与新建入口。选择项目、子项目后复用子项目任务表单，当前工位自动带入；两个入口维护同一条任务。任务必须属于一个子项目并指定一个工位，SOP 可以暂不选择，以待配置保存。后台校验所选项目的任务权限，资源管理权限不等于项目权限；工位任务清单仅展示有项目查阅权限的数据。

新增 GET /resource/station/{id}/task，返回项目、子项目、固定标准和配置缺项。创建与编辑继续使用 /project/{pid}/subproject/{sid}/task。未取消任务保存时必须指定工位；历史空工位任务保留并要求补齐，允许直接取消。数据库继续使用现有 sop_task.station_id，不修改旧数据或增加非空约束，本次不需要执行 SQL。

SOP 制作继续上传 PNG/JPEG 作为步骤底图并保存标注，不提供模拟视频或假 RTSP。任务入口带工位上下文；发布后提示返回子项目任务，显式选择发布版本。摄像头仍为未接入，上传图片不代表完成设备联调。


## 002 任务内容归属
