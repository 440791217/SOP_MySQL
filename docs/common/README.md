# 公共数据：前端业务编号

项目、子项目、SOP新建时由前端生成code，后台只校验并原样保存。当前没有流水服务和流水表依赖。内部id、已有编号和SOP的V1/V2版本规则保持不变。

| 类型 | 示例 |
|---|---|
| 项目 | PRJ-202610161745-A7F29C |
| 子项目 | SUB-202610161745-83BD16 |
| SOP | SOP-202610161745-C42E90 |

格式为类型前缀、12位年月日小时分钟、6位大写十六进制随机码，总长23。前端按Asia/Shanghai展示时间，并用浏览器crypto.getRandomValues取得3字节随机数。编号时间不是可信审计时间，created_at/published_at仍由后台控制。

## 数据库无需升级

现有code VARCHAR(64)、ASCII格式约束与唯一索引均适用，不需要新增、删除或修改业务表。项目和SOP各自全局唯一；子项目保持(project_id,code)项目内唯一，兼容旧数据。旧编号不批量重写，编辑接口不接受编号变更。

原common-module-v1/migrations/001_business_code_sequence.sql仅作为旧方案历史文件保留，**当前不要再执行**。流水表没有建好就不必建；已经建好的sop_business_code_sequence可原样保留闲置，应用不会读取或更新它。本次没有操作实际数据库，也没有提供自动删表脚本。

## 请求与重试

新建项目、子项目和SOP的POST请求必须携带code。后台检查对应PRJ/SUB/SOP前缀、长度、12位时间的有效日期时刻及大写随机码，不生成、修改或补全编号；不根据客户端时钟判断创建时间。旧格式只允许已有记录保留，新建必须使用新格式。

前端打开新建表单时生成一次编号，只读展示。校验失败、网络失败或409后保持表单和编号；再次提交沿用同一编号。取消并重新打开新建窗口才生成新编号。编号不是幂等令牌：若前一次提交已成功但响应丢失，重试会被唯一约束拒绝，先查询确认，避免重复新建。

时间加随机数降低冲突概率，但不保证绝对唯一，数据库唯一约束是最终兜底。编号重复返回HTTP409并明确提示，前端不静默换号或自动重试。删除后仍保留唯一约束，旧编号不能再次新建。

## 验证范围

前端覆盖上海时间、分钟补齐、随机后缀、同分钟不同随机码、创建请求、失败重试保留编号及编辑不改旧编号。后台通过独立H2/真实HTTP覆盖原样保存、缺编号、错前缀、无效日期、重复、软删除后重用拒绝及同编号并发只有一个成功。测试库不创建流水表，用于确认移除依赖。本次未连接真实MySQL写入或声称浏览器端到端验证。
